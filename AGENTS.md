# lvm-eval agent guide

## Purpose
Library of evaluation metrics for latent variable models. Receives model
outputs and targets; never contains models, weights, or training code.
First metric set: NLB (/projects/distil/_papers/NLB.pdf), reproduced exactly
and kept standalone. Reference implementation: github.com/neurallatents/nlb_tools.

## Hard constraints
- Pinned to /projects/murder via opam pin. Raven versions are whatever
  murder contains. Do not add other numerics libraries.
- OCaml Raven only for numerics/ML. No Python in the build or runtime.
  Python is used only to generate test fixtures, under reference/, outside dune.
- lvm-eval never depends on other projects (distil etc.).
- Core metric modules are pure: no file I/O, no global state, no model types.

## Data responsibility
- lvm-eval is data-agnostic. It never loads, stores, splits, aligns or
  defines data, and has no dataset configs. Callers (distil etc.) own all
  of that and pass tensors in.
- Metrics take held-in-derived model outputs, held-out model outputs and
  held-out targets as separate, clearly named arguments, with shapes and
  axis meanings documented. They do not validate alignment, only shape
  compatibility, and fail with clear errors.
- Anything that is part of a metric's definition in NLB.pdf / nlb_tools
  (smoothing, averaging, regression fitting, normalisation) lives inside
  lvm-eval. Anything that is data preparation lives in the caller. If it is
  unclear which, stop and ask.

## Testing and fixtures
- Tolerance: relative 1e-6 in float64. If Raven only gives float32 for an
  operation, state it and ask me before loosening.
- Golden values come from nlb_tools, generated outside the dune build.
- Fixtures: synthetic inputs for unit and edge-case tests, plus (if data
  is available) a small realistic case generated by the Python reference
  script. Committed fixtures are plain arrays of exactly what a caller would
  pass, plus expected values. Verify any real-data license before committing
  a slice.
- Every metric cites its source (paper section/equation and the nlb_tools
  file:function) in its doc comment.

## Working rules
- Never guess a Raven API; read murder's source or compile a check.
- Do not add dependencies or change the pinning without asking.
- Do not add abstractions for hypothetical future metrics beyond plan.md.
- Commit after each coherent step with a clear message. Do not push.
  Work directly on the main branch.
- If blocked or unsure, stop and ask using the format:
  QUESTION / WHY IT MATTERS / MY PROPOSED DEFAULT. Batch questions at the
  end of a task.
- Pause for my approval at the end of each phase.
